# Job Application Assistant

## What this tool does

Given a job posting URL (or pasted text), this tool produces:

1. **Eligibility score** — honest 100-point assessment of fit, broken down by stack match, experience, work authorisation, domain fit, and gap risk
2. **Tailored resume** — Markdown resume generated by Claude, emphasising the skills that match the specific posting
3. **Cover letter** — Markdown cover letter generated by Claude, addressing the honest gaps directly
4. **Financial analysis** — after-tax income calculated using the 2024 German tax formula (Steuerklasse I + social contributions), plus rent and disposable income estimates for Munich, Berlin, Leipzig, and Remote-DE
5. **Saved application record** — everything stored as JSON + Markdown files under `tools/job_assistant/output/<date>_<company>/`

The desk UI at `http://localhost:300x/desk` reads these output files and displays the full pipeline (score, status, financials, resume/cover letter viewer) without needing to run CLI commands.

## Current state (as of 2026-05-12)

The tool is **fully implemented and smoke-tested**. One real application has been run through it (TechCorp GmbH, score 73/100 — `apply_with_caveats`).

### What is working
- URL fetching (`requests` + `BeautifulSoup` HTML strip) with fallback to paste mode
- Job posting parser — extracts title, company, location, salary range, tech stack, contract type, remote flag, and language (DE/EN) via regex
- Eligibility assessor — all 5 scoring components functional, correct skill alias resolution (including `jest` → `Jest / TDD` which was a bug caught in testing)
- German tax calculator — 4-zone progressive formula (ZVE thresholds: 11,784 / 17,005 / 66,760 / 277,825), Werbungskosten deduction (€1,230), all 4 social contributions (KV 8.15%, PV 1.95%, RV 9.3%, AV 1.3%), Beitragsbemessungsgrenzen ceilings applied correctly
- City cost-of-living reports — Munich, Berlin, Leipzig, Remote-DE
- LLM generation — resume + cover letter + 5-sentence honest narrative via `claude-sonnet-4-6`, requires `ANTHROPIC_API_KEY` in `web/.env.local`
- Application storage and index (`output/index.json`)
- Status lifecycle: `saved → applied → interview → offer → rejected / withdrawn`
- Web desk integration — Job pipeline panel reads `index.json` and per-application JSON files via `/api/desk/jobs`

### What is not yet built
- **Automatic URL discovery** — you still need to find and paste the URL; there is no job board scraper/feed
- **Application email drafting** — the tool generates documents but does not send emails or interact with ATS portals
- **Follow-up reminders** — no calendar or notification integration for interview follow-ups
- **Multi-application comparison view** — desk shows cards but no side-by-side comparison or ranked shortlist

## Scoring rubric

| Component | Max | Logic |
|---|---|---|
| Stack match | 40 | Average skill score (0–10) across all detected tech keywords, scaled to 40 |
| Experience | 25 | Seniority detected from title (junior=1, mid=2, senior=3, lead=4+); Kundai's equivalent level is 2.5 (strong independent portfolio, no formal employment) |
| Work authorisation | 10 | Germany / EU remote = 10; Switzerland = 6; other = 3 |
| Domain fit | 15 | Base 8; +5 for AI-First (≥3 AI signals); +2 for domain bonus (legaltech, devtools, biotech, fintech, academic); +3 for developer-tooling |
| Gap risk | 10 | Base 5; +2 if AI-First; +1 if stack ≥32; −3 if ≥5 years required; −1 if ≥3 years required |

**Recommendation thresholds:**
- ≥75 → `apply`
- 58–74 → `apply_with_caveats`
- 42–57 → `stretch`
- <42 → `skip`

- Verifiable complex public portfolio (not toy projects)
- TDD proven by 30-test suite with a real bug caught by tests

**To add a new skill or alias**, edit `PROFILE["skills"]` and `SKILL_ALIASES` in `profile.py`. The alias map is important — job postings often use shorthands (`jest`, `ts`, `node`) that won't match the profile keys without it.

## Financial calculator

Uses the official 2024 German Einkommensteuergesetz formula:

```
ZVE = gross - Werbungskosten (€1,230)
Zone 1: ZVE ≤ 11,784       → 0% (Grundfreibetrag)
Zone 2: 11,784 < ZVE ≤ 17,005  → progressive (starts ~14%)
Zone 3: 17,005 < ZVE ≤ 66,760  → progressive (up to ~24%)
Zone 4: 66,760 < ZVE ≤ 277,825 → 42% minus Progressionsvorbehalt
Zone 5: ZVE > 277,825       → 45% (Reichensteuer)
```

Social contributions (employee share, 2024 rates):
- Krankenversicherung (KV): 8.15% — capped at BBG West (€5,175/mo gross)
- Pflegeversicherung (PV): 1.95% — same cap
- Rentenversicherung (RV): 9.3% — capped at BBG West
- Arbeitslosenversicherung (AV): 1.3% — same cap

Soli (Solidaritätszuschlag) is not charged at income levels relevant to this tool.

## CLI usage

Run all commands from the **repo root**:

```bash
# Analyse from URL (fetches HTML, falls back to paste if blocked):
python -m tools.job_assistant apply --url "https://example.com/job/123"

# Paste mode (most reliable — copy the full job description, then run):
python -m tools.job_assistant apply --paste

# Skip LLM generation (analysis only, no API key needed):
python -m tools.job_assistant apply --url "https://..." --no-generate

# List all saved applications:
python -m tools.job_assistant list

# Show a saved application:
python -m tools.job_assistant show 2026-05-11_techcorp_gmbh

# Update status after taking action:
python -m tools.job_assistant update 2026-05-11_techcorp_gmbh --status applied
```

## What to build next

**Priority 1 — Application email drafting**
Generate a short, professional email body to attach the resume to, ready to copy-paste or send directly. Should reference the specific role and company naturally.

**Priority 2 — Job board integration**
Instead of pasting URLs manually, pull open listings from LinkedIn/StepStone/Xing API or RSS feeds, filter by score threshold (e.g., auto-assess all listings ≥55), and surface them in the desk UI as a "Suggestions" feed.

**Priority 3 — ATS-aware resume format**
Current output is Markdown. Many German companies use Workable, Lever, or Greenhouse. Add a DOCX export (via `python-docx`) so the resume can be uploaded directly without formatting loss.

**Priority 4 — Follow-up tracker**
Add a `follow_up_date` field to the index and surface overdue follow-ups as alerts in the desk header (same `AlertBanner` system used for documents).
